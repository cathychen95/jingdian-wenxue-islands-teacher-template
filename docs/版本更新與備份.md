# 版本更新與備份

## 更新原則

更新時必須沿用原本的 Worker 與 D1 綁定。重新點擊部署按鈕建立另一套專案，會得到全新的空白資料庫。

本範本的部署指令會先以 D1 綁定名稱 `DB` 套用尚未執行的遷移，再發布 Worker。更新至 1.1.0 時，系統會建立單一學生登入索引；不會刪除學生、題庫、進度或作答紀錄。若舊資料庫曾留下同一學生的多個登入階段，只會保留最新一筆登入階段。

## 更新前

1. 從教師端匯出作答紀錄。
2. 保留原始學生名單與題庫 Excel。
3. 在 Cloudflare 確認目前 Worker 綁定的 D1 資料庫名稱。
4. 閱讀新版 `CHANGELOG.md`。

## 從 1.0.0 更新至 1.1.0

1. 確認仍使用原本的 Worker 與 D1 資料庫。
2. 將新版程式碼合併到教師自己的 GitHub repository。
3. 等候 Cloudflare Workers Builds 完成；部署指令會自動執行 D1 遷移。
4. 用測試學生檢查暱稱修改與不同裝置登入。
5. 若 Cloudflare 顯示遷移失敗，先停止更新，不要刪除 D1，並請具備 Cloudflare 管理權限的人協助確認綁定名稱仍為 `DB`。

## 教師帳密救援

部署 Secret 只負責第一次建立教師帳號。成功登入後，帳密會以不可還原的摘要保存在 D1。若忘記已生效的帳密，請由具備 Cloudflare 管理權限的人員依正式維護流程重設，不要刪除整個 D1 資料庫。

## 不應放進 ZIP 的內容

- `node_modules`
- `dist`
- `.wrangler`
- `.dev.vars`、`.env`
- Cloudflare Token
- 資料庫匯出檔
- 學生名單與作答紀錄
